# Kolekto

A C23 utility and type library providing foundational building blocks: custom data types, ranges, ASCII utilities, and I/O abstractions.

## Prerequisites

Install the required toolchain (Ubuntu/Debian):

```sh
sudo apt-get update && sudo apt-get install cmake ninja-build cppcheck gcovr -y
```

Or use the **Install toolchain** task in VS Code.

| Tool         | Purpose                         | Version |
| ------------ | ------------------------------- | ------- |
| **CMake**    | Build system generator          | >= 4.2  |
| **Ninja**    | Build executor (fast, parallel) | any     |
| **GCC**      | C23-capable compiler            | >= 13   |
| **Cppcheck** | Static analysis                 | any     |
| **gcovr**    | Code coverage reports           | any     |

## VS Code Integration

The `.vscode/` directory configures the IDE to work with the full toolchain out of the box.

### Settings (`.vscode/settings.json`)

- **CMake generator** set to Ninja for fast, parallel builds.
- **Coverage toolbar** enabled -- shows line-by-line coverage gutters directly in the editor.
- **Coverage info** pointed at `build/coverage.info` so VS Code can overlay coverage data on source files.
- **Post-run coverage** -- after running tests, VS Code automatically runs the `coverage` target to refresh the report.

### Tasks (`.vscode/tasks.json`)

Accessible via `Ctrl+Shift+B` (default build task) or the command palette:

| Task                    | What it does                                            |
| ----------------------- | ------------------------------------------------------- |
| **Build & Run Tests**   | Configures, builds, and runs all unit tests (default)   |
| **Build Kolekto**       | Configures, builds, and runs the main executable        |
| **Show Coverage Report** | Builds, runs tests, generates coverage, opens the HTML report |
| **Install toolchain**   | Installs cmake, ninja-build, cppcheck, gcovr via apt    |

## Build

```sh
cmake -B build -S .
cmake --build build
```

CMake configures the project into the `build/` directory using Ninja as the generator. The compiler is set to **C23** with strict warnings enabled (`-Wall -Wextra -Wpedantic -Werror` plus additional flags).

## Testing

```sh
ctest --test-dir build --output-on-failure
```

Tests use the [Unity](https://github.com/ThrowTheSwitch/Unity) test framework (v2.6.1), fetched automatically via CMake `FetchContent` on first configure. Test binaries are placed in `build/test/`.

## Static Analysis

Cppcheck runs automatically during the build via `CMAKE_C_CPPCHECK`. It scans both `src/` and `test/` with exhaustive checking enabled. Warnings are treated as errors (`--error-exitcode=1`).

Suppressions are listed in `cppcheck_suppressions.txt`:

- `missingIncludeSystem` -- system headers not found in the environment
- `unusedFunction` -- reported across translation units, often false positives
- `toomanyconfigs` -- complex macros generating many configurations
- `*:*/unity-*` -- suppress everything inside the fetched Unity library

## Code Coverage

Coverage is measured with **gcovr**, which processes `.gcda`/`.gcno` files generated by GCC's `--coverage` instrumentation.

### How it works

1. `--coverage` is passed to both the compiler and linker for test targets (see `test/CMakeLists.txt`). This instruments the binaries to record which lines and branches execute at runtime.
2. After tests run, the instrumented binaries write `.gcda` files (execution counts) into `build/test/CMakeFiles/`.
3. `cmake --build build --target coverage` runs gcovr, which reads the `.gcda` files and generates reports.

### Generate reports

```sh
cmake --build build --target coverage
```

This produces two outputs in `build/`:

| File            | Format | Description                                                                                       |
| --------------- | ------ | ------------------------------------------------------------------------------------------------- |
| `coverage.info` | LCOV   | Machine-readable, used by IDEs and CI tools                                                       |
| `coverage.html` | HTML   | Human-readable with per-file detail (`coverage.html` + `coverage.functions.html`, `coverage.css`) |

Open `build/coverage.html` in a browser to browse line-by-line coverage.

### Excluding directories

Directories like `lib/` (third-party code) and `build/` (build artifacts) are excluded from the report via `--exclude` flags in the `coverage` target (see `CMakeLists.txt`). To add more exclusions:

```cmake
COMMAND ${GCOVR}
    --exclude 'build/*'
    --exclude 'lib/*'
    --exclude 'test/*'        # add as needed
    --lcov ./build/coverage.info
```
